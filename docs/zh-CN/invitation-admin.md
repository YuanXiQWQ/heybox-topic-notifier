# 邀请注册与账号管理

## 权限

| 身份 | 权限 |
| --- | --- |
| `user`（用户） | 正常使用应用 |
| `admin`（管理员） | 普通用户权限，加上生成和撤销自己的邀请码 |
| `superadmin`（超级管理员） | 管理邀请码，以及查看、添加、编辑和删除账号 |

已有账号缺少 `role` 时按普通用户处理。注册提交中的身份、账号 ID 等声明不会决定新账号的权限。公开注册始终创建普通用户；超级管理员直接添加账号时可以选择身份。

## 首次指定超级管理员

只在可信的数据库管理入口中，核对本人账号的稳定 ID 后修改账号记录。不存在“首个注册者成为超级管理员”、初始化接口、环境变量提权或用户名自动匹配。

- Deno KV：修改 `["accounts", "本人账号 ID"]` 中的 `role` 为 `superadmin`，同时将 `roleVersion` 增加 1（原来没有则设为 1）。保留其余字段。
- Turso：角色在 `user_accounts.value_json` 中。只查询 `id` 和 `username` 来核对目标，不导出整条账号记录。核对后使用参数化 SQL：

```sql
UPDATE user_accounts
SET value_json = json_set(
  value_json,
  '$.role', 'superadmin',
  '$.roleVersion', COALESCE(json_extract(value_json, '$.roleVersion'), 0) + 1
)
WHERE id = ?;
```

任何人工修改身份都应同步增加 `roleVersion`，使已有管理再验证授权失效。在双写迁移期，数据库人工操作需要核对两端的一致性；迁移切换前必须解决镜像失败记录，不能把异步双写当作跨数据库事务。

日常通过超级管理员用户列表修改身份。普通资料保存、注册、邮箱与 Google 登录均不能修改身份。面板不允许删除自己或降低自己的身份，避免失去管理入口。不要把数据库凭据交给普通用户或管理员。

## 使用面板

管理员和超级管理员的账户菜单在“账户设置”和“退出登录”之间提供“管理员面板”。普通管理员没有用户列表和账号操作权限。

邀请码为 128 位随机值，支持每次生成 1–20 个、备注、可选有效期和撤销。完整邀请码仅在生成结果中展示；数据库保存摘要。保存好生成结果，遗失后撤销并重新生成。

超级管理员查看用户列表及执行账号操作前，需要用当前密码再验证；授权绑定当前登录会话，十分钟过期。只配置了 Google、邮箱或 Passkey 的超级管理员，应先在既有账户设置中配置密码。换一个登录会话不能复用再验证授权。

用户列表可编辑用户名、显示名称和身份。账号 ID、创建时间、邮箱及验证状态只读，避免直接编辑登录索引造成账号混淆。密码仅展示配置状态；密码摘要、盐、验证码、会话令牌、恢复码、TOTP 密钥均不返回页面。添加用户的密码在服务端使用现有加盐 PBKDF2 实现处理后才写入数据库。

删除需输入目标用户名确认。账号和用户名索引删除后，旧会话不能继续使用；服务端清理凭据、会话、设备订阅和业务数据，保留防恢复标记及邀请码使用记录。数据库清理失败会返回失败，需排查后完成清理，不能据此恢复旧账号。设备上此前保存的离线副本不可能在设备离线时远程擦除；重新联网访问仍受服务端账号检查约束。

## 注册及一致性

用户名注册、邮箱首次登录和 Google 首次登录均需邀请码。已有账号登录、绑定登录方式和正常业务功能不需要邀请码。邮箱或 Google 身份验证完成后，新身份先进入短期邀请码表单；表单绑定当前浏览器，未核销前不会创建正式账号。

账号、必要凭据与邀请码核销在权威数据库中原子提交。并发只能成功一次；账号创建冲突不消耗邀请码。网络中断后可重新登录确认结果，重复请求不会再次创建账号。删除账号不会恢复邀请码。

KV 与 Turso 均实现同一契约；迁移副本复制已提交的结果，不重新执行兑换。临时注册资料和管理员再验证授权不跨库复制。切换权威数据库后，需要重新完成尚未结束的注册或管理再验证。

## 安全边界

- 管理接口每次读取数据库身份，写入事务再次检查操作者权限；不能依赖隐藏菜单授权。
- 管理写请求校验 CSRF 和请求来源，限制请求体、频率和批量生成数量。
- 用户字段白名单、HTML 转义、参数化 SQL 和权限版本检查共同防止字段注入、脚本注入及旧表单覆盖权限。
- 管理页面使用 `no-store`，不加入 Service Worker 离线页面名单，不加载彩蛋交互，不增加彩蛋候选槽位。
- 审计记录动作、操作者、目标 ID 和结果，不记录密码、邀请码原文或数据库凭据。
- 现有登录人机验证、登录限制和已启用的双重验证流程继续生效。
